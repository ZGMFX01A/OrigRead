Designing resilient offline readers

An offline reader is useful only when its content pipeline is observable and recoverable. Fetching, extraction, sanitization, scoring, and caching should be separate stages with clear failure boundaries.

Static HTML remains the cheapest path. Structured metadata and explicit selectors can provide high-confidence candidates, while a readability algorithm handles pages without dedicated rules.

Fallback behavior is part of the product, not merely an error state.

When extraction fails, the interface should explain whether the page is dynamic, restricted, unavailable, or simply lacks a recognizable article body. Users must still be able to open the original page.
