## 2. 第一次使用：添加第一个来源

### 2.1 直接添加一个网站、RSS 或 Feed

1. 在首页选择 **+ 添加**，进入添加来源。
2. 粘贴网站首页、文章列表页、RSS/Atom Feed 或其他来源地址。
3. 开始检测后等待原读完成分析。检测期间会显示当前正在检查的阶段。
4. 查看结果列表。原读会默认推荐更适合订阅的候选；如果同时出现多个候选，也可以自己选择。
5. 确认后添加来源，返回时间线等待首次同步完成。

你不需要事先判断一个网站到底有没有 RSS。对于普通网页，原读会自动尝试可用方式。

### 2.2 候选类型怎么选

| 看到的候选 | 适合什么情况 | 一般怎么选 |
| --- | --- | --- |
| **RSS / Atom** | 网站本身提供标准 Feed | 通常优先，稳定且开销小 |
| **RSSHub** | RSSHub 已有对应路由 | 路由可用时很方便；同一网站可能有多个频道 |
| **JSON/API** | 网站存在稳定公开接口或结构化数据 | 通常比网页选择器更不容易受页面样式改版影响 |
| **Website** | 没有可用 Feed，但网页本身有稳定文章列表 | 可以使用；网站大改版后可能需要重新选择规则 |
| **动态网页** | 文章列表必须执行 JavaScript 后才出现 | 作为最后兜底，速度通常比前几种慢 |

如果一个网站同时给出多个可用候选，不必追求“技术上最高级”的那个。**时间线能稳定更新、标题和链接正常，就是更重要的判断标准。**

### 2.3 从 OPML 导入已有订阅

如果你已经在其他 RSS 阅读器里有订阅：

1. 先在原阅读器中导出 `.opml` 或 `.xml` 文件。
2. 在原读的添加入口选择 **导入 OPML**。
3. 选择文件并确认导入。
4. 导入完成后检查分组和来源数量。

OPML 主要负责迁移标准订阅。Website Rule、JSON Rule、RSSHub 设置、AI/翻译配置等原读专属内容，请使用后面的“完整配置备份”。

## 3. 阅读一篇文章

### 3.1 在来源正文、全文和原文之间切换

阅读时常见的三种内容不是一回事：

- **来源正文**：RSS/Atom/JSON 本身提供的内容。有些来源只给一小段摘要。
- **全文**：原读访问文章页后提取出的正文，适合沉浸阅读、搜索、翻译和 AI 摘要。
- **原文**：网站真实页面。全文提取不完整、需要查看评论/图表/交互内容时使用。

如果当前来源只提供摘要，可以切换到全文；如果全文仍不理想，直接打开原文即可。

### 3.2 已读、收藏和文章切换

阅读页可以直接：

- 标记已读 / 未读；
- 收藏 / 取消收藏；
- 切换上一篇 / 下一篇；
- 搜索当前文章；
- 打开原始网页。

这些状态和普通阅读操作不需要 AI。

## 4. 使用 AI 摘要

### 4.1 第一次使用前先配置 AI 服务

1. 打开 **设置 → AI 阅读**。
2. 添加一个 OpenAI Compatible 服务。
3. 填写服务地址；需要鉴权时再填写 API Key。
4. 获取或填写模型，并选择默认模型。
5. 使用 **测试连接** 确认当前配置可以正常访问。
6. 保存并启用该服务。

可以同时配置多个服务。默认服务只决定“平时短按时用谁”，并不会限制你临时切换。

### 4.2 生成当前文章的摘要

1. 打开一篇文章。
2. **短按 AI 按钮**。
3. 原读会按当前默认服务、模型和摘要档位开始生成。
4. 生成期间会显示当前阶段和已等待时间。
5. 如果不想继续，选择 **停止生成摘要**。

成功的摘要会缓存。文章正文发生变化后，旧摘要不会被当成新正文的摘要继续复用。

### 4.3 临时换一个模型或摘要长度

**长按 AI 按钮**。

长按会打开本次摘要的选项，可以临时选择：

- AI 服务；
- 模型；
- 速览 / 均衡 / 深入摘要档位。

这种临时选择只影响本次生成，不需要为了偶尔换模型去修改全局默认设置。

## 5. 翻译文章

### 5.1 第一次使用前配置翻译方式

打开 **设置 → 翻译设置**，选择并启用需要的翻译服务，然后设置默认目标语言。

Android 可以使用传统翻译服务，也可以使用 AI 全文翻译。是否配置 AI 摘要，不影响传统翻译服务正常使用。

### 5.2 使用默认翻译方式

1. 打开文章。
2. **短按翻译按钮**。
3. 原读使用当前默认翻译方式和目标语言处理文章。
4. 翻译完成后，可以按当前阅读模式查看译文或原文/译文对照。

### 5.3 临时切换翻译服务或目标

**长按翻译按钮**。

长按用于这一次临时选择其他已启用的翻译方式/目标；需要时也可以把选择设为新的默认值。

如果长按后没有可选项，先回到 **设置 → 翻译设置**，确认至少有一个服务已启用并且目标语言有效。

## 6. 把文章分享到笔记软件

文章阅读页的分享不再只是发送一个链接，也可以把文章内容一起带走，而且原文 URL 始终会保留。

### 6.1 第一次使用先选择分享内容

1. 打开一篇文章。
2. 点击 **分享**。
3. 第一次使用时，选择 **使用标题和链接**，或者选择 **自定义内容**。
4. 自定义时可以选择文章标题、原文正文、已生成的翻译和摘要。
5. 保存后，从 Android 系统分享面板选择目标应用。

设置完成后，短按分享会直接按照上次的选择发送；想修改内容时，长按 **分享** 按钮即可重新设置。这个设置只影响文章阅读页，列表页原来的分享方式不变。

### 6.2 分享过去是什么格式

原读会优先发送富文本 HTML；不支持 HTML 的应用会收到 Android 带样式文本或纯文本回退。文章里的图片会保留为外链地址，不会把图片文件复制到笔记里。

翻译或摘要只有在当前阅读页已经打开时才会分享。即使之前生成过缓存，只要当前没有打开，也不会自动带过去。目标应用取决于设备上安装的笔记软件：Obsidian 可以自动创建新笔记，Notion 需要先在分享设置中配置个人访问令牌。

## 7. 朗读文章

- **短按朗读按钮**：开始或停止朗读。
- **空闲时长按朗读按钮**：尝试打开 Android 系统 TTS 设置，可以在那里更换朗读引擎和系统语音。

当译文正在作为主要阅读内容显示时，朗读会优先针对当前正在阅读的译文；AI 摘要区域有自己的朗读入口。

## 8. 添加来源失败怎么办

### 8.1 先看原读停在哪个阶段

添加来源时，界面会显示正在检查的方式，例如 RSS/Atom、RSSHub、JSON/API、静态网页或动态网页。

如果某一步较慢，先等待该阶段结束，不需要反复关闭弹窗重新添加。

### 8.2 “动态 WebView 兜底”是什么意思

有些网站在服务器最初返回的 HTML 里没有文章列表，必须等 JavaScript 执行后才显示内容。普通网页解析看不到这些文章时，原读会在最后自动尝试 **WebView 动态渲染**。

你不需要手动开启这个步骤。

这和“AI 生成网站规则”里的 **用浏览器渲染重试** 不是同一个步骤：添加来源时的动态解析是系统自动兜底；AI 生成规则时只有在普通请求失败后，页面明确显示重试按钮，你才需要手动触发。这样不会让后台刷新被浏览器渲染拖慢。

如果动态页面最终识别出了真实文章链接，但稳定性不够高，原读可能提示类似“**应用可能无法正确处理该来源**”。这时可以：

1. 先看候选是否真的有正常文章标题和数量。
2. 如果内容看起来合理，可以尝试添加。
3. 添加后观察一两次刷新是否仍能正常更新。
4. 如果后续经常解析失败，删除该来源并改用 RSS/RSSHub/规则会更稳。

**仅仅网页打开成功不算订阅成功。** 如果动态页面最终没有识别到可用文章链接，原读不会创建一个 0 篇文章的空来源。

### 8.3 浏览器能打开，但原读还是无法添加

常见原因包括：

- 网站需要登录；
- 有验证码或浏览器挑战；
- 内容必须经过复杂交互后才出现；
- 页面没有稳定的文章列表结构；
- 网站限制了自动请求；
- 当前网络无法访问对应 RSSHub/API。

原读不会绕过登录、验证码、付费墙或网站访问控制。遇到这种情况，优先寻找该站官方 RSS、RSSHub 路由或公开 API。

## 9. 管理 RSSHub

### 9.1 配置 RSSHub 实例

打开 **设置 → RSSHub**。

你可以：

1. 启用或停用 RSSHub；
2. 使用内置实例；
3. 添加自己的公共/自建实例地址；
4. 单独测试某个实例；
5. 删除不需要的实例。

### 9.2 “已匹配”为什么还不能订阅

原读会先在本地判断网址是否匹配 RSSHub 路由，再访问具体 RSSHub 实例。因此：

**已匹配到路由 ≠ 当前实例一定能生成 Feed。**

常见状态可以这样理解：

- **可订阅**：路由和实例都正常，Feed 也通过检查；
- **实例响应超时 / 当前实例不可访问**：路由已经找到，但这次实例连接失败；
- **实例未返回有效 Feed**：实例有响应，但内容不是可用 Feed；
- **Feed 内容未通过质量检查**：拿到了内容，但结果不适合直接作为时间线来源；
- **需要更具体的页面地址**：当前网址缺少生成这条 RSSHub 路由所需的参数。

公共实例有波动时，可以稍后重试或换实例；不需要因此删除本地 RSSHub 路由数据。

## 10. 过滤不想看的文章

文章过滤适合“这个来源我想订阅，但其中一部分标题我永远不想看到”的情况。

可以使用：

- 标题关键词；
- 正则表达式；
- 全局范围或来源范围的规则（以当前规则类型提供的范围为准）。

过滤发生在**新文章进入正常时间线之前**。新增过滤规则不会回头删除历史文章，避免规则写错造成不可逆损失。

## 11. 使用 Website Rule / JSON API Rule

### 11.1 什么时候用 Website Rule

网站没有稳定 Feed，但文章列表直接存在于 HTML 中，而且页面结构比较稳定时使用。

Website Rule 通过页面元素选择文章卡片、标题、链接、时间等字段。网站改版后选择器可能失效。

### 11.2 什么时候用 JSON/API Rule

网站有稳定公开 REST/JSON 或其他结构化接口时使用。相比网页选择器，稳定 API 通常更不容易被视觉改版影响。

### 11.3 规则怎么管理

规则页支持导入、导出、启用/停用、测试和删除，并提供更详细的规则格式说明。

### 11.4 使用 AI 生成网站规则

AI 生成适合“网页没有现成 Feed，想先得到一个可验证的规则候选”的情况。它不是把任意网站变成稳定订阅的保证，网站改版或访问限制仍然会影响结果。

1. 打开 **设置 → 网站解析规则 → AI 生成网站规则**。
2. 填写包含文章列表的页面地址。应该填写列表页，例如新闻首页、分类页或搜索结果页；不要先填某一篇文章的正文地址。
3. 页面会自动带入 AI 设置中的默认服务和模型。确认无误后再开始生成；如果有多个已启用服务，可以在这里临时切换。
4. 点击 **开始生成**。界面会依次显示抓取页面、分析结构、生成候选、使用本地解析器验证等阶段。
5. 先看候选结果中的文章数量、评分和样例标题。只有确实解析出了你想订阅的文章，才点击 **保存规则**。

生成过程默认先用普通网页请求，速度快、资源占用低。如果页面依赖 JavaScript，或普通请求被网站拦截，页面会显示失败阶段、失败原因以及 **用浏览器渲染重试**。只有在这种情况下手动点重试，应用才会用一次受控的浏览器渲染重新获取页面。它可能更慢，也可能仍然失败。

应用不会绕过登录、验证码、付费墙或其他访问控制。浏览器里能打开，不代表应用可以在没有登录状态的情况下生成规则。

### 11.5 正文规则为什么单独显示

列表规则和正文规则分两个阶段：

- 列表阶段负责找出文章标题、链接和时间，并必须先通过真实试跑；
- 正文阶段会再尝试访问若干篇详情页，让 AI 找出正文区域，并用本地提取器验证；
- 正文生成或验证失败时，列表规则仍然可以保存。打开文章时会继续使用通用正文解析，必要时可以使用内置 WebView 兜底。

候选页里如果显示“正文规则已通过验证”，表示正文选择器在样例文章上可用；如果显示“未生成”或“生成失败”，请把它理解为正文增强没有完成，不是列表规则也失效了。详情页被登录、验证码、跨站跳转或反爬拦截时，正文规则可能无法生成，这是网站访问条件造成的限制，不应阻塞列表订阅。

### 11.6 使用 AI 生成 JSON/API 规则

在 **设置 → JSON/API 规则** 中打开 AI 生成，填写公开的 JSON/API 地址或包含内嵌 JSON 的页面。选择服务和模型后开始生成，查看识别到的来源类型、文章数量、评分和样例，再保存候选。

JSON 规则的正文阶段只会在返回数据中确实存在可复用的正文路径时生成；没有正文字段或路径验证失败时，仍然可以保存列表规则。JSON 生成不会因为列表请求失败而自动打开浏览器，也不会绕过登录或验证码。

如果生成失败，先看页面写明的失败阶段和原因，再决定是换模型、换地址，还是改用规则模板和手工配置。不要把错误提示中的技术堆栈当成操作步骤。

如果你只是普通使用者，不需要为了添加一个常见网站先学会写规则；优先让“添加来源”自动发现，只有自动方式确实不够时再考虑规则。

## 12. 迁移与备份

### 12.1 OPML 和“完整配置备份”有什么区别

| 需求 | 使用什么 |
| --- | --- |
| 从其他 RSS 阅读器导入/导出订阅 | **OPML** |
| 在 Android 与 Desktop 之间迁移原读专属配置 | **完整配置备份** |
| 迁移 Website/JSON 规则、过滤、RSSHub、AI/翻译设置 | **完整配置备份** |
| 迁移原读 X 的 Custom Instructions、Web Search、MCP 等扩展设置 | **完整配置备份** |
| 只想带走标准 RSS 订阅 | **OPML** |

### 12.2 导出完整配置

打开 **设置 → 备份与恢复**，选择导出配置。

完整配置主要用于迁移“设置和订阅”，不会把文章正文、已读/收藏历史、AI 摘要缓存、翻译缓存等全部当作备份内容复制过去。

敏感凭据默认不包含在备份中。如果明确选择 **包含凭据**，需要设置备份密码；迁移到另一台设备时使用同一密码恢复。普通 AI/翻译 API Key，以及原读 X 支持的 Web Search Key、MCP Token / Header / OAuth 凭据都会放进加密凭据块，而不是明文写进备份文件。

## 13. 账户与同步

### 13.1 Local 账户

如果你主要使用 OrigRead 自己的 RSSHub、Website、JSON/API、规则和本地阅读能力，使用 Local 即可。

### 13.2 FreshRSS / Google Reader Compatible / Fever Compatible

这些账户用于连接对应协议的自建或第三方服务。远端账户能做什么，取决于远端协议真正提供的能力。

Website、JSON/API、RSSHub 是 OrigRead 自己扩展的来源类型，因此属于 Local 账户，不会伪装成远端服务原生支持的来源。

如果你不需要跨设备服务器同步，不必为了“功能更全”专门创建远端账户。

GitHub 版本可以在应用内检查 OrigRead Android 的新 Release，并下载适合当前设备的 APK。

Android 8 及以上首次从应用安装 APK 时，系统可能要求你授权“允许安装未知应用”。这是 Android 系统权限页，不是原读自己的账号或权限申请。

## 15. 常见问题

### 15.1 网站返回 403 / 418

网站可能区分普通程序请求和真实浏览器请求，也可能对访问频率、地区或网络环境有限制。原读会按自己的安全边界尝试正常解析，但不会绕过网站访问控制。

### 15.2 RSSHub 明明“已匹配”，为什么没有可订阅项？

“已匹配”只说明本地找到了路由。继续看状态提示：实例超时、实例不可访问、Feed 无效或质量检查失败都可能让这次结果不可订阅。

### 15.3 AI 按钮不可用

打开 **设置 → AI 阅读**，确认至少有一个服务已启用、模型已选择并能通过连接测试。

### 15.4 翻译按钮长按后没有可选服务

打开 **设置 → 翻译设置**，确认至少启用了一个翻译服务，并检查目标语言。

### 15.5 全文提取不完整

先切换到原文确认网页本身内容是否完整。如果网页依赖复杂交互、登录或特殊脚本，全文提取可能无法覆盖全部内容；原文入口始终是最后退路。

### 15.6 动态网页来源刷新比较慢

动态来源需要启动 WebView、等待页面执行脚本并再次解析，速度本来就会比标准 RSS 慢。能找到 RSS/RSSHub/API 时，优先使用这些方式通常更稳定。

# 第二部分：原读 X 操作手册

> **本部分只适用于原读 X。**
>
> 原读 X 包含第一部分的全部基础阅读能力。这里仅说明 X 新增的文章问答、多文章上下文、Web Search、MCP、Skills、快捷消息等功能，避免和普通版操作混在一起。

## X1. 原读 X 是什么

原读 X 保留普通版的阅读方式，在此基础上增加了“围绕文章继续问、联网查、调用工具、组合多篇文章”等能力。它的重点仍然是**当前文章和你明确选中的上下文**，不是在阅读器里另外塞一个和文章无关的通用聊天软件。

如果你只需要订阅、阅读、摘要和翻译，前面的普通功能照常使用，不需要配置下面所有扩展。

## X2. 打开 AI 阅读助手

先按前面的步骤配置好至少一个可用的 AI 服务和模型，然后打开任意文章。

常用入口有三个：

1. **长按 AI 按钮**，在“AI 阅读”面板里选择 **询问这篇文章**，进入 AI 阅读助手。
2. 在同一个面板里选择 **深度分析**，原读 X 会直接以当前文章为上下文发起一次深入分析。
3. 如果摘要已经生成，摘要面板右上角也可以直接进入“询问这篇文章”。

正文里选中一段文字后，系统菜单里还会出现 **AI**。点它会把这段选中文字带进阅读助手，适合直接问“这句话什么意思”“这段推理有没有问题”等问题。

## X3. 会话、服务和模型怎么用

阅读助手的会话按文章保存。打开会话历史可以切换旧会话，也可以新建、重命名或删除会话。

输入框附近可以直接切换当前会话使用的 **AI 服务和模型**。这里的切换针对当前对话使用，不需要为了临时换模型反复回设置页改默认值。

生成过程中可以停止；已经生成的回答可以复制或重新生成。模型或服务如果明确返回 reasoning，且你在设置中允许显示，也可以展开查看；没有返回就不会凭空生成一段“思考过程”。

## X4. 一次带上多篇文章

有些问题只看当前文章不够，例如想比较两篇报道、把后续报道和旧文章放在一起看。

1. 在阅读助手输入区点击 **+**。
2. 从最近文章里选择，或者按标题搜索。
3. 点选需要附加的文章。当前最多可以额外加入 **5 篇**。
4. 不需要时可以移除某一篇，或者清空附加文章。

打开“添加相关文章”面板本身不会把所有候选文章都发给模型，**只有你真正点选的文章才会进入当前会话上下文**。

## X5. 看清这次回答到底用了什么

回答旁边可以查看 **本次回答的上下文**。这里会列出当前文章、相关文章、摘要、译文、选中文字、网络搜索结果和 Tool 结果等，并标明：

- **已使用**：实际进入了本次模型请求；
- **已使用 · 已截断**：用了，但为了控制长度只保留了一部分；
- **未纳入**：这次没有发送给模型。

如果你一次放入很多长文章、搜索结果或 Tool 结果，内容可能超过 Context Budget。遇到回答明显缺资料时，先看这里，比单纯把 Context Budget 调得越来越大更容易判断问题出在哪。

## X6. 快捷消息：把常用问题做成按钮

打开 **设置 → AI 阅读 → 管理快捷消息**，可以新增、编辑、启用、排序或删除常用提示，例如“解释难点”“检查证据”“按时间线整理”。

阅读助手输入区的 **⋮** 可以直接打开已启用的快捷消息。点一下就会把它当成一条普通用户消息发送，不会偷偷修改 System Prompt，也不会自动获得 MCP/Tool 权限。

自定义快捷消息可以使用当前文章标题、文章地址、选中文字、已有摘要等变量。某个变量当前不存在时，原读 X 会直接提示，而不是发送一条残缺的模板。

## X7. Custom Instructions：设置长期回答习惯

打开 **设置 → AI 阅读 → 编辑 Custom Instructions**，可以写长期偏好，例如：

- 用简洁中文回答；
- 保留英文技术术语；
- 区分事实和推断；
- 优先使用紧凑 Markdown。

它会影响文章对话、AI 摘要和 AI 翻译的回答风格，但**不会给模型增加 Tool、MCP 或其他权限**。

## X8. 模型推理强度、流式输出和 Context Budget

在 **设置 → AI 阅读** 的 X 专属设置区可以调整：

- **模型推理强度**：Auto / Low / Medium / High。只有模型和服务本身支持时才会生效；
- **流式输出**：打开后，回答会边生成边显示；
- **显示服务返回的推理内容**：只显示服务明确返回的 reasoning；
- **Context Budget**：控制一次请求最多给文章上下文留多少空间，默认 128K tokens。

这些不是“越大越好”的性能开关。正常使用保持默认即可，只有你经常组合很长的文章和外部资料时才需要调整。

## X9. Web Search：需要最新信息时再联网

先打开 **设置 → AI 阅读 → Web Search**，再进入 **管理 Web Search**：

1. 添加一个搜索服务；
2. 按该服务要求填写 API Key 或自托管 Endpoint；
3. 点 **测活**，确认它真的能返回搜索结果；
4. 需要时设为默认服务，并调整每次返回的结果数。

配置完成后，阅读助手输入区会出现地球图标。它有三种模式：

- **关闭**：这次对话不做专用网络搜索；
- **自动**：只有问题明显在问“最新、今天、近期、当前进展”或明确要求联网搜索时才会搜索；
- **下一条强制联网**：只强制搜索下一条消息，发出后自动恢复原来的默认模式。

搜索过程和结果会显示在对应回答里。你可以打开结果列表，也可以在“本次回答的上下文”里确认哪些结果真的进入了模型。

自动模式的目标是少打扰、少浪费搜索额度，不是每个问题都先上网。如果问题本身只是在解释当前文章，通常不会触发搜索。

## X10. MCP：让阅读助手使用你配置的外部工具

如果你不知道 MCP 是什么，可以完全不配置，不影响摘要、翻译、文章对话和 Web Search。

需要使用时，打开 **设置 → AI 阅读 → MCP → 管理 MCP**：

1. 添加 MCP Server，填写名称和 Endpoint；
2. 按服务要求选择无认证或 OAuth 2.1；需要网关 Header 时可以填写 Custom Headers；
3. OAuth 服务按页面提示完成授权；
4. 使用 **测活/刷新** 确认连接正常并成功发现 Tools。

模型支持标准 Tool Calling 时，阅读助手可以按需要请求 Tool。被标记为敏感或写入型的操作会先要求你 **允许 / 拒绝**，不会直接替你执行。

如果当前模型不支持标准 Tool Calling，但已经配置了 MCP，输入区可能提供 **MCP Tool** 手动入口。你可以自己选择 Tool、确认参数，再把执行结果作为上下文附加给模型。

## X11. Skills：给特定任务准备一套说明书

打开 **设置 → AI 阅读 → Skills** 可以导入或新建 Skill。Skill 可以理解为一套针对特定任务的说明和参考资料，例如固定一种文章分析方法。

- 单文件 Skill 可以直接导入/编辑 `SKILL.md`；
- 文件夹型 Skill 可以把整个目录打成 ZIP 后导入；
- 打开 Skills 总开关后，文章对话会按请求匹配已安装 Skill；
- 也可以给支持的固定任务指定一个 Skill。

Skill 主要用于给模型提供指令和资料。导入包里的脚本不会被原读 X 当成任意本地程序直接执行。

## X12. 原读和原读 X 之间同步时会带什么

普通版和 X 版可以并存。版本间同步仍以已有同步入口为准，不需要先卸载另一版。

X 版现在会把自己的高级设置纳入配置迁移，包括 Custom Instructions、运行参数、Web Search 配置和 MCP Server 配置等。API Key、MCP Token、Custom Headers、OAuth 凭据这类敏感信息只有在同步/备份明确包含凭据时才会进入加密数据。

普通版不认识 X 专属功能，因此同步到普通版不会把普通版“变成 X 版”；反过来从普通版同步到 X 版时，也不会因为普通版没有这些字段就把 X 版已有的专属凭据清空。

## X13. 原读 X 常见问题

### X13.1 AI 阅读助手没有 Web Search / MCP / Skills 入口

先打开 **设置 → AI 阅读** 检查对应总开关和配置。Web Search 至少要有一个已经配置好的搜索服务；MCP 至少要有一个能正常发现 Tools 的 Server；Skills 需要先安装 Skill 并打开 Skills 总开关。没有配置完成的扩展不会为了“看起来功能很多”而一直显示无效入口。
