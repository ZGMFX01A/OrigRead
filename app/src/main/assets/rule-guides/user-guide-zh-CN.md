## 2. 添加来源：把网址交给原读就行

订阅不一定要从 RSS 地址开始。你可以直接给原读一个网站首页或栏目页，让它寻找可用的文章来源。没有现成 Feed 的网站，也可能通过 RSSHub、网页文章列表或公开接口订阅。

### 2.1 添加第一个来源

1. 在首页点 **+ 添加**，粘贴网站首页、栏目页、RSS / Atom 或公开 API 地址。
2. 开始检测，等待候选结果出现。检测中会显示当前正在检查的来源类型。
3. 预览候选中的文章，确认标题、链接和栏目符合预期，再选择要订阅的结果。
4. 确认添加，回到时间线等待首次同步。

想追踪某个专栏时，优先粘贴专栏的列表页；单篇文章的网址不一定能找到这个专栏的全部更新。还没有想好的来源，可以在**发现来源**中按名称、分类或关键词浏览。

### 2.2 原读能从哪里找到文章

| 来源方式 | 它能帮你订阅什么 | 选择时看什么 |
| --- | --- | --- |
| **RSS / Atom** | 网站提供的标准订阅，原读也会尝试从网页中寻找 Feed 地址 | 内容完整、更新正常时，通常直接选它 |
| **RSSHub** | RSSHub 已有路由支持的网站、频道或栏目 | 预览是否是你要的栏目，以及当前实例能否正常返回内容 |
| **网页解析（Website）** | 没有 Feed，但页面上有规律排列的文章列表 | 标题和文章链接是否正确，有没有混入导航或广告 |
| **JSON / API** | 公开文章接口、WordPress 文章数据，以及部分 Next.js / Nuxt 页面内的数据 | 返回的是否是需要的文章，而非其他页面数据 |
| **动态网页** | 必须加载并执行网页脚本后才出现的文章列表 | 等待渲染后再看结果，留意低可信提示和文章数量 |

同一个网址可能找到几种结果。原读会根据文章数量、标题、链接和时间等信息检查并排序；推荐结果可以作为起点，但最终应以预览里的文章是否符合你的需求为准。选择会随来源保存，后续刷新继续使用。

如果一个栏目有稳定的 Feed 或公开接口，可以优先使用；网页解析和动态渲染则为更多网站提供了订阅机会。某种方式失败时，原读还会尝试其他可用方式，无需先替它判断网址的类型。

### 2.3 配置 RSSHub 实例

RSSHub 路由说明“怎样从这个网站获取文章”，实例则是实际提供内容的服务。找到路由后，仍需有可用实例才能订阅。

打开 **设置 → RSSHub**，添加或启用一个可访问的实例，并测试连接。可以配置多个实例，也可以使用自己的 RSSHub 服务；不需要在手机上运行 RSSHub 服务器。匹配成功却读不到内容时，先检查实例状态，详见[添加来源失败怎么办](#9-添加来源失败怎么办)。

### 2.4 从其他阅读器迁移

在旧阅读器导出 OPML，再从原读的添加入口选择**导入 OPML**，即可带入标准订阅和分组。

网页规则、JSON 规则、RSSHub 实例，以及翻译和 AI 设置，需要通过[完整配置备份](#12-备份版本间同步和账户)迁移。OPML 无法代替这些设置。

## 3. 阅读文章：先分清来源正文、全文和原文

打开时间线中的文章，就可以开始阅读。遇到内容太短、图片缺失或想看评论时，先分清这三个入口：

| 内容 | 适合什么时候看 |
| --- | --- |
| **来源正文** | Feed 或接口直接提供的内容，可能是全文，也可能只是摘要 |
| **全文** | 原读从文章网页提取出的正文，适合连续阅读、翻译和 AI 分析 |
| **原文** | 网站上的原始页面，适合查看评论、互动图表或提取时遗漏的内容 |

如果来源只给了几行摘要，尝试获取全文；仍不完整时，打开原文查看。第一次提取全文可能需要等待，Citation 跳转到尚未加载的文章时也可能先加载正文。

阅读页可以标记已读、收藏、切换上一篇或下一篇、搜索文内文字，也可以调整阅读外观。手机以单栏阅读为主；Pad 和大屏会根据可用空间保留列表、正文或 AI 面板，方便对照阅读。

## 4. 第一次使用 AI：先把服务配通

想生成摘要或围绕文章提问，先在 **设置 → AI 阅读** 中连接一个服务。

1. 添加 OpenAI 兼容服务，填写服务提供的 **Base URL** 或完整接口地址。
2. 按服务要求填写 **API Key**，获取模型列表或手动填写模型名称。
3. 选择默认模型，点**测试连接**。
4. 测试成功后保存并启用，回到文章尝试生成摘要。

地址、密钥和模型名称都以服务提供方给出的信息为准。可以添加多个服务，在某次摘要或对话中临时切换，不必反复修改默认配置。

### 4.1 决定 AI 按钮打开什么

**AI 对话助手**和**阅读页摘要**两个开关决定阅读页主按钮的用途：

| AI 对话助手 | 阅读页摘要 | 点 AI 主按钮 |
| --- | --- | --- |
| 关闭 | 无需设置 | 生成摘要 |
| 开启 | 开启 | 优先生成摘要，也可进入文章对话 |
| 开启 | 关闭 | 直接进入文章对话，空白会话中仍有快捷摘要 |

“阅读页摘要”开关只在对话助手开启时显示。关闭对话助手会隐藏对话、搜索、MCP 和 Skills 入口；历史会话和配置仍然保留，再开启即可继续使用。

## 5. 摘要和 AI 阅读助手怎么配合

### 5.1 先看摘要，再决定细读哪里

在阅读页打开摘要，按需要选择**速览 / 均衡 / 深入**。生成时会显示进度阶段和等待时间，长文章或响应较慢的模型可能需要多等一会儿。

生成成功的摘要会保留，正文未变化时可再次查看。想换个角度或详细程度，可以重新选择服务、模型和摘要档位再生成；这次选择不会改变全局默认值。主按钮直接进入对话时，也可以使用空白会话中的快捷摘要。

### 5.2 带着文章提问

开启 AI 对话助手后，从 AI 面板进入**询问这篇文章**，或将主按钮设为直接打开对话。你可以问“作者最主要的论据是什么？”“这一段和前面的说法矛盾吗？”。

只想问某句话时，在正文中选中文字，再从选择菜单进入 AI，无需手动复制粘贴。回答以文章原文为依据；需要核对时，可以使用下一节介绍的 Citation。

### 5.3 继续上次的讨论

会话按文章保存，可以新建、切换、重命名或删除；服务和模型可以在输入区附近切换。生成中可以停止，已有回答可以复制或重新生成。模型提供推理内容且显示设置开启时，回答中也会展示这部分内容。

## 6. Citation：回答里的引用真的可以回到原文

Citation 让你在回答和原文之间来回核对。读到一个结论时，顺手看看它依据哪句话，再回到回答继续读。

### 6.1 点引用，查看原文依据

1. 在回答中找到 `[1]`、`[2]` 等引用标记并点开。
2. 如果这处引用包含多个来源，选择想查看的出处。
3. 原读打开对应文章，定位并高亮被引用的文字。读一下前后文，就能判断这段话是否支持回答中的结论。

引用可以来自当前文章，也可以来自附加文章。尚未加载全文时，需要先等待正文载入；不必自己退出对话去找文章。

### 6.2 从正文返回回答

点正文中的 Citation 标记，可以回到**引用它的那次会话和那条回答**，并定位到对应的回答段落。

试着把两篇报道放进同一次对话，问“它们对事件原因的解释有什么不同？”先点回答里的引用去看第一篇，再返回回答查看第二篇。即使依据分布在不同文章里，也能沿着同一次讨论继续核对和追问。

### 6.3 想自己翻正文时

引用正在自动滚动时，直接拖动页面即可接手阅读，原读会取消这次自动定位。你可以自由查看上下文，需要重新定位时再点引用。

### 6.4 不同引用会打开哪里

文章引用会定位到阅读页正文；联网搜索引用保留网页出处，工具结果保留相应工具来源。

如果网站后来改写了文章，或旧引用已无法准确匹配，原读会提供来源供你查看。引用便于检查依据，AI 的理解是否准确，仍需要结合原文判断。

## 7. 需要更多上下文时，再加多文章、搜索和工具

### 7.1 比较几篇文章

在阅读助手输入区点 **+**，从最近文章或标题搜索结果中选择相关文章，最多额外加入 **5 篇**。选好后再提问，例如“请比较这几篇文章的共同观点和分歧”。

只有你选中的附加文章才会随问题提供给 AI。“本次回答参考内容”可以查看实际使用了哪些文章、搜索结果或工具结果；长文过多时，部分内容可能因长度限制而截取或省略。

### 7.2 查背景或近期进展

在 **设置 → AI 阅读 → Web Search** 中配置搜索服务，按要求填写密钥和服务地址，先测试是否可用。

| 搜索模式 | 适合什么时候用 |
| --- | --- |
| **关闭** | 只想围绕已提供的内容讨论 |
| **自动** | 问题涉及近期进展，或明确要求联网查找 |
| **下一条强制联网** | 希望下一次提问一定搜索，发送后恢复原模式 |

回答会展示相关搜索过程和结果，你可以查看搜索了什么、参考了哪些网页。

### 7.3 连接自己的工具

MCP 用来连接外部工具，普通阅读和文章问答无需配置。需要时进入 **设置 → AI 阅读 → MCP**，添加服务地址，按提供方要求配置认证，再测试连接并刷新工具列表。

模型支持工具调用时，可以在回答过程中请求这些工具。敏感或会写入数据的操作会先请你允许或拒绝；部分场景也可手动选择工具、确认参数，把结果提供给 AI。

### 7.4 保存常用的提问方式

**快捷消息**适合“列出关键论据”这类经常重复的问题；**自定义指令（Custom Instructions）**适合“用中文回答，先解释术语”这类长期偏好。

**Skills**可以保存一套更完整的方法和参考资料，例如固定的文章分析框架。支持导入单个 `SKILL.md` 或包含 Skill 文件夹的 ZIP。导入后，模型可以使用其中的说明和资料；原读不会执行包内脚本。

推理强度、流式输出和推理内容显示按模型支持情况调整即可。**Context Budget**控制一次问答能容纳多少内容：经常同时加入多篇长文时，可以查看参考内容是否被省略，再决定减少附件或调整预算。

## 8. 翻译、分享和朗读

### 8.1 对照译文阅读

1. 打开 **设置 → 翻译设置**，启用一种翻译服务并选择目标语言。
2. 回到文章，点翻译按钮，使用默认设置翻译。
3. 在翻译选项中选择仅看译文或分段对照，也可临时更换服务和语言。

设备端可选 Google ML Kit；云端可选 Microsoft Translator、DeepL、Google Cloud 或自建 DeepLX / DLX 兼容服务。配置好的 OpenAI 兼容模型也能用于全文翻译。普通翻译服务可以独立使用，无需先配置 AI。

长文章会分批翻译，可能需要更多时间。AI 翻译会尽量保留段落顺序和结构，适合对照阅读；遇到难懂的表达，可以切回原文查看。

### 8.2 分享到笔记或其他应用

在阅读页点**分享**，首次使用时选择要发送的内容：标题、正文，以及当前已打开的译文和摘要。原文链接会一同保留。

之后短按分享沿用上次选择，**长按分享按钮**可以修改。想带上译文或摘要，先在当前阅读页打开它们；以前生成过但现在没有打开的内容不会附带发送。

原读会尽量保留排版；目标应用是否支持富文本，会影响最终效果。图片以外链保留，不会作为图片文件一起复制过去。

### 8.3 听文章

点朗读按钮开始或停止 TTS。正在显示译文时，优先朗读译文；摘要区域也有自己的朗读入口。更换声音或朗读引擎，需要到 Android 系统的文字转语音设置中调整。

## 9. 添加来源失败怎么办

### 9.1 检测一直没有结束

先看当前阶段。RSS 和公开接口通常较快，网页解析、RSSHub 请求或动态页面加载可能需要更多时间。某一种方式失败后，原读还会继续尝试其他方式，可以等本次检测结束再决定是否重试。

如果结果不符合预期，换成具体栏目页的地址再试，通常比网站首页更容易找到所需文章。

### 9.2 动态页面很慢，或提示解析结果不可靠

动态页面需要先加载网页、执行脚本，再从显示出来的内容中找文章，因此比直接读取 Feed 更慢。

**页面能打开，不代表文章一定能被识别。** 某些动态网页候选即使没有找到可靠列表，也允许你在看到风险提示后尝试添加；这不保证后续能正常刷新。先检查文章数量、标题和链接，有稳定 Feed、RSSHub 或公开接口时优先选择它们。

### 9.3 浏览器能打开，原读却读不到

浏览器里可能已有登录状态，页面也可能要求验证码、特定操作或订阅权限。原读无法绕过这些条件；可以寻找网站提供的 Feed、可用 RSSHub 路由或公开接口，正文则通过原文页面查看。

### 9.4 RSSHub 已匹配，但没有内容

“已匹配”表示找到了对应路由，实际文章仍要由 RSSHub 实例返回。实例超时、无法访问或返回的内容无效，都会影响订阅。

到 **设置 → RSSHub** 测试当前实例，必要时更换或启用另一个实例，再重试。无需因为一次连接失败就删除路由数据。

### 9.5 提交解析问题

仍无法订阅时，欢迎[提交 Issue](https://github.com/ZGMFX01A/OrigRead/issues)。附上网址、应用版本、预期订阅的栏目，以及检测阶段或错误提示，方便复现问题。

## 10. 什么时候才需要 Website Rule / JSON API Rule

当自动发现的结果已经满足需求，就不必另写规则。需要指定栏目、排除混入的内容，或修正正文提取范围时，再用规则做更细的调整。

### 10.1 选择规则类型

**网站解析规则（Website Rule）**适合从网页里找文章列表，也可指定正文区域。**JSON / API 规则**适合读取公开接口或网页内嵌的文章数据。

在 **设置 → 网站解析规则**或 **JSON 规则**中，可以管理、导入、导出和测试规则。需要手动编辑时，先查看规则页内的使用说明，里面有字段解释和示例。

### 10.2 请 AI 帮忙生成

1. 打开对应规则管理页，进入 AI 生成入口。
2. 填入栏目列表页或公开 API 地址，选择已配置的 AI 服务和模型。
3. 等待生成和试跑，查看文章数量、样例标题、链接和评分。
4. 确认得到的是你想订阅的文章后再保存。

如果普通抓取失败，而页面需要加载脚本，网站规则生成页可能提供**用浏览器渲染重试**，可以按提示再试一次。

### 10.3 怎样判断规则可用

先看解析出的文章是否来自目标栏目，标题和链接是否正确；数量多、评分高都不能代替这一步。保存后刷新来源，确认能持续获取内容。

“能找到文章”和“能提取完整正文”是两件事。列表正确但正文不完整时，可以继续使用列表规则，再调整正文规则或打开原文阅读。网站改版后重新测试，必要时更新规则。

## 11. 过滤不想看的文章

想保留某个来源，又不想反复看到某类标题，可以在 **设置 → 文章过滤**中添加关键词或正则规则，按规则页提供的范围选择全局或指定来源。

保存前先确认关键词是否过于宽泛；例如只屏蔽某个栏目名称，通常比单个常见字更合适。使用正则时，需要先通过表达式检查。规则可以单独启停，也支持导入和导出。

过滤针对之后进入时间线的新文章，**不会删除已经保存的历史文章**。发现过滤过多时，先停用或修改规则，再观察后续更新。

## 12. 备份、版本间同步和账户

### 12.1 根据要迁移的内容选择方式

| 想做什么 | 使用什么 |
| --- | --- |
| 把标准订阅和分组带到另一个阅读器 | OPML |
| 换设备后继续使用原来的订阅、规则和偏好 | 完整配置备份 |
| 同一台设备上，把数据交给另一个已安装的原读版本 | 版本间同步 |
| 在多台设备间同步远端账户支持的内容 | 对应账户的同步服务 |

**完整配置备份不包含文章正文、已读与收藏状态，也不包含摘要和翻译缓存。** 它可以带走订阅、分组、解析规则、过滤、RSSHub、翻译、AI，以及搜索、工具等相关设置。

### 12.2 导出与恢复配置

1. 打开 **设置 → 备份与恢复**，选择**导出完整配置**，保存备份文件。
2. 在目标设备的同一页面选择**恢复配置**，打开备份文件。
3. 核对订阅数量等信息；文件含有加密密钥时，输入备份密码，再确认恢复。

相同网址的订阅会合并，缺少的会新增；目标设备上其他已有订阅和文章历史会保留。部分界面设置可能需要重启应用后生效。

### 12.3 一并迁移密钥

备份默认不导出密钥。需要带上 AI、翻译或 MCP 等服务的已保存凭据时，在导出前开启**包含已保存的密钥**，并设置至少 6 个字符的备份密码。

恢复时需要输入同一密码。原读不会保存这个密码，请自行妥善保管。

### 12.4 同一设备上的版本间同步

两版功能一致，正常更新无需更换应用。确实需要在 OrigRead 与 OrigRead X 之间迁移时，先确保两者都已安装，再在 **备份与恢复**中选择**同步到原读**或**同步到原读 X**，到接收方核对信息并确认。

版本间同步可以迁移共有设置，以及当前账户的订阅、文章、已读、星标和稍后读状态，支持的已保存密钥也可一并迁移。它与导出配置文件的范围不同；仅存在于接收方的版本专属数据会保留。

### 12.5 选择本地或远端账户

主要使用原读的 RSSHub、网页解析、JSON/API 和本地阅读功能时，选择 **Local（本地）**即可。

已有 FreshRSS、Google Reader Compatible 或 Fever Compatible 服务时，可以添加对应账户。哪些内容能同步，取决于远端服务；原读扩展的网页、JSON/API 和 RSSHub 来源不能假定会被这些协议完整支持。

## 13. 软件更新

在 **设置 → 软件更新**中可以手动检查更新，也可以选择是否在启动时检查。应用会显示更新说明，并下载与当前安装版本对应的 APK。

已有用户继续更新原来的包即可。OrigRead 与 OrigRead X 功能一致，仅默认配置略有不同；保留两个包，是为了让你沿用现有应用和设置，无需迁移。

第一次从应用安装 APK 时，Android 可能要求开启**允许安装未知应用**。按系统提示授权后，继续安装即可。

## 14. 常见问题

| 遇到的情况 | 可以先这样处理 |
| --- | --- |
| **AI 按钮不可用** | 在“设置 → AI 阅读”确认服务已启用、模型已选择，并通过连接测试 |
| **想问文章，按钮却只生成摘要** | 开启“AI 对话助手”，再关闭“阅读页摘要”，主按钮就会直接进入对话 |
| **Citation 没定位到预期文字** | 等待全文加载；文章被改写后，旧引用可能只能打开来源，参见 [Citation](#6-citation回答里的引用真的可以回到原文) |
| **翻译没有可用服务** | 在“设置 → 翻译设置”启用服务，确认目标语言；AI 翻译还需可用模型 |
| **全文提取不完整** | 尝试重新提取，或打开原文查看缺失部分；规则调整见[解析规则](#10-什么时候才需要-website-rule--json-api-rule) |
| **网站返回 403 / 418** | 检查网址和网络，稍后重试；网站可能限制访问频率、地区或自动请求 |
| **Pad 和手机布局不同** | 功能相同，布局按屏幕空间调整，Pad 可以保留更多列表、正文和 AI 上下文 |

找不到答案时，可以通过[问题反馈](https://github.com/ZGMFX01A/OrigRead/issues)提供应用版本、操作步骤和错误提示。项目目前不接受 Pull Request，建议和文档纠错也请提交 Issue。
