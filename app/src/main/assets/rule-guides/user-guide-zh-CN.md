## 第一次使用：添加第一个来源

### 直接添加一个网站、RSS 或 Feed

1. 在首页选择 **+ 添加**，进入添加来源。
2. 粘贴网站首页、文章列表页、RSS/Atom Feed 或其他来源地址。
3. 开始检测后等待原读完成分析。检测期间会显示当前正在检查的阶段。
4. 查看结果列表。原读会默认推荐更适合订阅的候选；如果同时出现多个候选，也可以自己选择。
5. 确认后添加来源，返回时间线等待首次同步完成。

你不需要事先判断一个网站到底有没有 RSS。对于普通网页，原读会自动尝试可用方式。

### 候选类型怎么选

| 看到的候选 | 适合什么情况 | 一般怎么选 |
| --- | --- | --- |
| **RSS / Atom** | 网站本身提供标准 Feed | 通常优先，稳定且开销小 |
| **RSSHub** | RSSHub 已有对应路由 | 路由可用时很方便；同一网站可能有多个频道 |
| **JSON/API** | 网站存在稳定公开接口或结构化数据 | 通常比网页选择器更不容易受页面样式改版影响 |
| **Website** | 没有可用 Feed，但网页本身有稳定文章列表 | 可以使用；网站大改版后可能需要重新选择规则 |
| **动态网页** | 文章列表必须执行 JavaScript 后才出现 | 作为最后兜底，速度通常比前几种慢 |

如果一个网站同时给出多个可用候选，不必追求“技术上最高级”的那个。**时间线能稳定更新、标题和链接正常，就是更重要的判断标准。**

### 从 OPML 导入已有订阅

如果你已经在其他 RSS 阅读器里有订阅：

1. 先在原阅读器中导出 `.opml` 或 `.xml` 文件。
2. 在原读的添加入口选择 **导入 OPML**。
3. 选择文件并确认导入。
4. 导入完成后检查分组和来源数量。

OPML 主要负责迁移标准订阅。Website Rule、JSON Rule、RSSHub 设置、AI/翻译配置等原读专属内容，请使用后面的“完整配置备份”。

## 阅读一篇文章

### 在来源正文、全文和原文之间切换

阅读时常见的三种内容不是一回事：

- **来源正文**：RSS/Atom/JSON 本身提供的内容。有些来源只给一小段摘要。
- **全文**：原读访问文章页后提取出的正文，适合沉浸阅读、搜索、翻译和 AI 摘要。
- **原文**：网站真实页面。全文提取不完整、需要查看评论/图表/交互内容时使用。

如果当前来源只提供摘要，可以切换到全文；如果全文仍不理想，直接打开原文即可。

### 已读、收藏和文章切换

阅读页可以直接：

- 标记已读 / 未读；
- 收藏 / 取消收藏；
- 切换上一篇 / 下一篇；
- 搜索当前文章；
- 打开原始网页。

这些状态和普通阅读操作不需要 AI。

## 使用 AI 摘要

### 第一次使用前先配置 AI 服务

1. 打开 **设置 → AI 阅读**。
2. 添加一个 OpenAI Compatible 服务。
3. 填写服务地址；需要鉴权时再填写 API Key。
4. 获取或填写模型，并选择默认模型。
5. 使用 **测试连接** 确认当前配置可以正常访问。
6. 保存并启用该服务。

可以同时配置多个服务。默认服务只决定“平时短按时用谁”，并不会限制你临时切换。

### 生成当前文章的摘要

1. 打开一篇文章。
2. **短按 AI 按钮**。
3. 原读会按当前默认服务、模型和摘要档位开始生成。
4. 生成期间会显示当前阶段和已等待时间。
5. 如果不想继续，选择 **停止生成摘要**。

成功的摘要会缓存。文章正文发生变化后，旧摘要不会被当成新正文的摘要继续复用。

### 临时换一个模型或摘要长度

**长按 AI 按钮**。

长按会打开本次摘要的选项，可以临时选择：

- AI 服务；
- 模型；
- 速览 / 均衡 / 深入摘要档位。

这种临时选择只影响本次生成，不需要为了偶尔换模型去修改全局默认设置。

## 翻译文章

### 第一次使用前配置翻译方式

打开 **设置 → 翻译设置**，选择并启用需要的翻译服务，然后设置默认目标语言。

Android 可以使用传统翻译服务，也可以使用 AI 全文翻译。是否配置 AI 摘要，不影响传统翻译服务正常使用。

### 使用默认翻译方式

1. 打开文章。
2. **短按翻译按钮**。
3. 原读使用当前默认翻译方式和目标语言处理文章。
4. 翻译完成后，可以按当前阅读模式查看译文或原文/译文对照。

### 临时切换翻译服务或目标

**长按翻译按钮**。

长按用于这一次临时选择其他已启用的翻译方式/目标；需要时也可以把选择设为新的默认值。

如果长按后没有可选项，先回到 **设置 → 翻译设置**，确认至少有一个服务已启用并且目标语言有效。

## 朗读文章

- **短按朗读按钮**：开始或停止朗读。
- **空闲时长按朗读按钮**：尝试打开 Android 系统 TTS 设置，可以在那里更换朗读引擎和系统语音。

当译文正在作为主要阅读内容显示时，朗读会优先针对当前正在阅读的译文；AI 摘要区域有自己的朗读入口。

## 添加来源失败怎么办

### 先看原读停在哪个阶段

添加来源时，界面会显示正在检查的方式，例如 RSS/Atom、RSSHub、JSON/API、静态网页或动态网页。

如果某一步较慢，先等待该阶段结束，不需要反复关闭弹窗重新添加。

### “动态 WebView 兜底”是什么意思

有些网站在服务器最初返回的 HTML 里没有文章列表，必须等 JavaScript 执行后才显示内容。普通网页解析看不到这些文章时，原读会在最后自动尝试 **WebView 动态渲染**。

你不需要手动开启这个步骤。

这和“AI 生成网站规则”里的 **用浏览器渲染重试** 不是同一个步骤：添加来源时的动态解析是系统自动兜底；AI 生成规则时只有在普通请求失败后，页面明确显示重试按钮，你才需要手动触发。这样不会让后台刷新被浏览器渲染拖慢。

如果动态页面最终识别出了真实文章链接，但稳定性不够高，原读可能提示类似“**应用可能无法正确处理该来源**”。这时可以：

1. 先看候选是否真的有正常文章标题和数量。
2. 如果内容看起来合理，可以尝试添加。
3. 添加后观察一两次刷新是否仍能正常更新。
4. 如果后续经常解析失败，删除该来源并改用 RSS/RSSHub/规则会更稳。

**仅仅网页打开成功不算订阅成功。** 如果动态页面最终没有识别到可用文章链接，原读不会创建一个 0 篇文章的空来源。

### 浏览器能打开，但原读还是无法添加

常见原因包括：

- 网站需要登录；
- 有验证码或浏览器挑战；
- 内容必须经过复杂交互后才出现；
- 页面没有稳定的文章列表结构；
- 网站限制了自动请求；
- 当前网络无法访问对应 RSSHub/API。

原读不会绕过登录、验证码、付费墙或网站访问控制。遇到这种情况，优先寻找该站官方 RSS、RSSHub 路由或公开 API。

## 管理 RSSHub

### 配置 RSSHub 实例

打开 **设置 → RSSHub**。

你可以：

1. 启用或停用 RSSHub；
2. 使用内置实例；
3. 添加自己的公共/自建实例地址；
4. 单独测试某个实例；
5. 删除不需要的实例。

### “已匹配”为什么还不能订阅

原读会先在本地判断网址是否匹配 RSSHub 路由，再访问具体 RSSHub 实例。因此：

**已匹配到路由 ≠ 当前实例一定能生成 Feed。**

常见状态可以这样理解：

- **可订阅**：路由和实例都正常，Feed 也通过检查；
- **实例响应超时 / 当前实例不可访问**：路由已经找到，但这次实例连接失败；
- **实例未返回有效 Feed**：实例有响应，但内容不是可用 Feed；
- **Feed 内容未通过质量检查**：拿到了内容，但结果不适合直接作为时间线来源；
- **需要更具体的页面地址**：当前网址缺少生成这条 RSSHub 路由所需的参数。

公共实例有波动时，可以稍后重试或换实例；不需要因此删除本地 RSSHub 路由数据。

## 过滤不想看的文章

文章过滤适合“这个来源我想订阅，但其中一部分标题我永远不想看到”的情况。

可以使用：

- 标题关键词；
- 正则表达式；
- 全局范围或来源范围的规则（以当前规则类型提供的范围为准）。

过滤发生在**新文章进入正常时间线之前**。新增过滤规则不会回头删除历史文章，避免规则写错造成不可逆损失。

## 使用 Website Rule / JSON API Rule

### 什么时候用 Website Rule

网站没有稳定 Feed，但文章列表直接存在于 HTML 中，而且页面结构比较稳定时使用。

Website Rule 通过页面元素选择文章卡片、标题、链接、时间等字段。网站改版后选择器可能失效。

### 什么时候用 JSON/API Rule

网站有稳定公开 REST/JSON 或其他结构化接口时使用。相比网页选择器，稳定 API 通常更不容易被视觉改版影响。

### 规则怎么管理

规则页支持导入、导出、启用/停用、测试和删除，并提供更详细的规则格式说明。

### 使用 AI 生成网站规则

AI 生成适合“网页没有现成 Feed，想先得到一个可验证的规则候选”的情况。它不是把任意网站变成稳定订阅的保证，网站改版或访问限制仍然会影响结果。

1. 打开 **设置 → 网站解析规则 → AI 生成网站规则**。
2. 填写包含文章列表的页面地址。应该填写列表页，例如新闻首页、分类页或搜索结果页；不要先填某一篇文章的正文地址。
3. 页面会自动带入 AI 设置中的默认服务和模型。确认无误后再开始生成；如果有多个已启用服务，可以在这里临时切换。
4. 点击 **开始生成**。界面会依次显示抓取页面、分析结构、生成候选、使用本地解析器验证等阶段。
5. 先看候选结果中的文章数量、评分和样例标题。只有确实解析出了你想订阅的文章，才点击 **保存规则**。

生成过程默认先用普通网页请求，速度快、资源占用低。如果页面依赖 JavaScript，或普通请求被网站拦截，页面会显示失败阶段、失败原因以及 **用浏览器渲染重试**。只有在这种情况下手动点重试，应用才会用一次受控的浏览器渲染重新获取页面。它可能更慢，也可能仍然失败。

应用不会绕过登录、验证码、付费墙或其他访问控制。浏览器里能打开，不代表应用可以在没有登录状态的情况下生成规则。

### 正文规则为什么单独显示

列表规则和正文规则分两个阶段：

- 列表阶段负责找出文章标题、链接和时间，并必须先通过真实试跑；
- 正文阶段会再尝试访问若干篇详情页，让 AI 找出正文区域，并用本地提取器验证；
- 正文生成或验证失败时，列表规则仍然可以保存。打开文章时会继续使用通用正文解析，必要时可以使用内置 WebView 兜底。

候选页里如果显示“正文规则已通过验证”，表示正文选择器在样例文章上可用；如果显示“未生成”或“生成失败”，请把它理解为正文增强没有完成，不是列表规则也失效了。详情页被登录、验证码、跨站跳转或反爬拦截时，正文规则可能无法生成，这是网站访问条件造成的限制，不应阻塞列表订阅。

### 使用 AI 生成 JSON/API 规则

在 **设置 → JSON/API 规则** 中打开 AI 生成，填写公开的 JSON/API 地址或包含内嵌 JSON 的页面。选择服务和模型后开始生成，查看识别到的来源类型、文章数量、评分和样例，再保存候选。

JSON 规则的正文阶段只会在返回数据中确实存在可复用的正文路径时生成；没有正文字段或路径验证失败时，仍然可以保存列表规则。JSON 生成不会因为列表请求失败而自动打开浏览器，也不会绕过登录或验证码。

如果生成失败，先看页面写明的失败阶段和原因，再决定是换模型、换地址，还是改用规则模板和手工配置。不要把错误提示中的技术堆栈当成操作步骤。

如果你只是普通使用者，不需要为了添加一个常见网站先学会写规则；优先让“添加来源”自动发现，只有自动方式确实不够时再考虑规则。

## 迁移与备份

### OPML 和“完整配置备份”有什么区别

| 需求 | 使用什么 |
| --- | --- |
| 从其他 RSS 阅读器导入/导出订阅 | **OPML** |
| 在 Android 与 Desktop 之间迁移原读专属配置 | **完整配置备份** |
| 迁移 Website/JSON 规则、过滤、RSSHub、AI/翻译设置 | **完整配置备份** |
| 只想带走标准 RSS 订阅 | **OPML** |

### 导出完整配置

打开 **设置 → 备份与恢复**，选择导出配置。

完整配置主要用于迁移“设置和订阅”，不会把文章正文、已读/收藏历史、AI 摘要缓存、翻译缓存等全部当作备份内容复制过去。

API Key 默认不包含在备份中。如果明确选择 **包含 API Key**，需要设置备份密码；迁移到另一台设备时使用同一密码恢复。

## 账户与同步

### Local 账户

如果你主要使用 OrigRead 自己的 RSSHub、Website、JSON/API、规则和本地阅读能力，使用 Local 即可。

### FreshRSS / Google Reader Compatible / Fever Compatible

这些账户用于连接对应协议的自建或第三方服务。远端账户能做什么，取决于远端协议真正提供的能力。

Website、JSON/API、RSSHub 是 OrigRead 自己扩展的来源类型，因此属于 Local 账户，不会伪装成远端服务原生支持的来源。

如果你不需要跨设备服务器同步，不必为了“功能更全”专门创建远端账户。

## 常见问题

### 网站返回 403 / 418

网站可能区分普通程序请求和真实浏览器请求，也可能对访问频率、地区或网络环境有限制。原读会按自己的安全边界尝试正常解析，但不会绕过网站访问控制。

### RSSHub 明明“已匹配”，为什么没有可订阅项？

“已匹配”只说明本地找到了路由。继续看状态提示：实例超时、实例不可访问、Feed 无效或质量检查失败都可能让这次结果不可订阅。

### AI 按钮不可用

打开 **设置 → AI 阅读**，确认至少有一个服务已启用、模型已选择并能通过连接测试。

### 翻译按钮长按后没有可选服务

打开 **设置 → 翻译设置**，确认至少启用了一个翻译服务，并检查目标语言。

### 全文提取不完整

先切换到原文确认网页本身内容是否完整。如果网页依赖复杂交互、登录或特殊脚本，全文提取可能无法覆盖全部内容；原文入口始终是最后退路。

### 动态网页来源刷新比较慢

动态来源需要启动 WebView、等待页面执行脚本并再次解析，速度本来就会比标准 RSS 慢。能找到 RSS/RSSHub/API 时，优先使用这些方式通常更稳定。
